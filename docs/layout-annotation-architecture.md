# 画像注釈エディタ設計（矢印・枠・テキスト）

## 1. 実装方式の比較

### A. 素のSVG + React state（今回採用）
- 長所
  - 依存ライブラリ不要（現行スタック維持）
  - データをJSONで直列化しやすく、localStorage保存に相性が良い
  - Print/PDF出力時に同じDOMを流用しやすい
- 短所
  - 高度機能（回転、レイヤー管理、スナップ、履歴）を自作する必要

### B. Fabric.js
- 長所
  - 図形編集機能が豊富で実装速度が速い
- 短所
  - 依存が重く、React統合の管理コストが上がる
  - Canvas中心のため、印刷時の品質・再編集データ設計を別途整理しやすい

### C. Konva + react-konva
- 長所
  - Reactとの親和性が高く、操作イベントが扱いやすい
- 短所
  - 依存追加が必要
  - SVG/DOMベースと比較して印刷・アクセシビリティ対応で追加実装が増える

## 2. 推奨ライブラリ
- 現時点の推奨: **ライブラリ追加なし（素のSVG実装）**
- 理由
  - 既存プロジェクトが軽量構成（Next + React）
  - 要件が「矢印/枠/テキスト + 色変更 + 保存/再編集」で収まる
  - PDF/印刷へそのまま反映しやすい
- 将来、回転・複雑選択・履歴分岐などが増える場合は `react-konva` への移行を再検討

## 3. アーキテクチャ設計
- データモデル（Project内）
  - `layoutImageDataUrl: string`（配置図画像）
  - `layoutAnnotations: LayoutAnnotation[]`（注釈JSON）
- 注釈型
  - `arrow`: `fromX/fromY/toX/toY/strokeWidth/color`
  - `rect`: `x/y/width/height/strokeWidth/color`
  - `text`: `x/y/text/fontSize/color`
- 座標系
  - 正規化座標（`0..1000`）で保存
  - 表示サイズが変わっても再配置が崩れにくい
- 保存
  - 既存の `projects -> localStorage` 保存に同梱
  - テンプレート保存/案件コピーにも `layoutAnnotations` を含める
- 出力
  - PDF7プレビューと印刷ページで、画像 + SVGオーバーレイを同じデータで描画

## 4. サンプル構成

### UIフロー
1. PDF7カードで画像をアップロード
2. `注釈編集へ遷移` ボタンで編集モーダルを開く
3. ツール選択（選択/矢印/枠/テキスト）
4. 色・太さを変更
5. 保存
6. 再度 `注釈編集へ遷移` で再編集

### コンポーネント責務
- `LayoutAnnotatedImage`
  - 画像 + 注釈の共通描画（通常プレビュー/印刷）
- `PlannerApp` 内エディタモーダル
  - 編集操作（追加・移動・削除・保存）
- ストレージ
  - `normalizeProject` で旧データ互換を維持

### 追加された主な操作
- 矢印作成: ドラッグ
- 枠作成: ドラッグ
- テキスト作成: クリック配置
- 移動: `選択` ツールでドラッグ
- 色変更: カラーピッカー + 選択要素へ適用
