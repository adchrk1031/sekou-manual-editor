# tracking / auth 運用チェックリスト

更新日: 2026-05-27

## 目的

第2段階で整えた権限 / 監査 / セッション運用を、人が確認しやすい形で固定する。

## ログイン / 承認

- 初期管理者登録が 1 回だけ行える
- 一般ユーザー登録後は `pending` になる
- `pending` ユーザーはログインできない
- `approved` かつ active なユーザーのみ利用できる
- `rejected` ユーザーはログイン不可

## セッション切れ

- セッション期限切れ時は `/` へ戻る
- 一定時間未操作でも `/` へ戻る
- 戻った際に再ログイン理由が表示される
  - 期限切れ
  - 未操作タイムアウト
  - 利用権限の再確認失敗

## 案件アクセス

- private 案件は所有者本人と管理者のみ見える
- private 案件は所有者本人と管理者のみ編集できる
- shared 案件は承認済みユーザーが閲覧できる
- `viewer` は shared 案件でも編集不可
- アクセス切替時に監査ログが残る

## 監査ログ

- ユーザー絞り込みができる
- 画面単位で絞り込みできる
- 操作単位で絞り込みできる
- 主要操作の確認例
  - `project_create`
  - `project_delete`
  - `project_access_update`
  - `csv_apply`
  - `template_apply`

## 編集ロック

- 編集中の案件はロック保持される
- 他ユーザー編集中は編集不可メッセージが出る
- ロック解除後は再編集できる

## リリース前の最低確認

1. 承認済み editor でログインできる
2. private 案件を作成し、同一ユーザーで見える
3. 別の一般ユーザーでは private 案件が見えない
4. 管理者では private 案件が見える
5. アクセス切替ができ、監査ログへ残る
6. セッション切れ後に `/` で再ログイン案内が出る
