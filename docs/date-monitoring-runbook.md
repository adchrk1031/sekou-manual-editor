# 日付健全性 運用ランブック（Step 9）

## 目的
- 日付ズレ（+1日化）の再発を早期検知し、PDF出力までの整合性を維持する。

## 運用タイミング
- 毎日の作業開始前に1回
- CSV一括投入の直後
- GASや画面ロジックを更新した直後

## 実行メニュー
- `施工計画書 > 日付回帰チェック`
  - 期待値固定の自己テストを実行
  - `NG` の場合はリリース停止
- `施工計画書 > 日付健全性スキャン`
  - `案件一覧` 全行を走査
  - Date型混在 / 不正形式 / 警告を集計

## 判定基準
- 回帰チェック: 失敗数 `0` が合格
- 健全性スキャン:
  - `Date型混在 = 0` を目標
  - `不正フォーマット = 0` を必須
  - 警告（例: 停電時刻なし）は業務ルールに沿って解消

## 検出時の対応
1. 実行ログ（Executions）で対象 `project_id` / 行番号 / フィールド名を確認
2. 該当セルを文字列形式に修正
   - `work_date_main`: `YYYY-MM-DD`
   - `planned_outage_start/end`: `YYYY-MM-DD HH:mm`
   - `work_time_start/end`: `HH:mm`
3. 再度 `日付回帰チェック` と `日付健全性スキャン` を実行
4. 両方合格後にPDF再出力

## 禁止事項
- 業務日付を `Date` 型のまま再保存しない
- `toISOString()` 等のUTC変換で業務日付を作らない
- PDF出力直前に業務日付を `Date` 化して再解釈しない
